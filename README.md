# VCR AR Explorer

**Team:** Shrawan Kolekar (612302029) · Archit Shelar (612302057) — Robotics & AI  
**Guide:** Dr. Shubhangi Deshmukh · Mechanical Engineering Department, COEP Tech, Pune  
**Live site:** https://shrawan3035.github.io/VCR-AR-Explorer/

Interactive 3D / AR learning module for a **Vapour Compression Refrigeration (VCR)** system:
an original procedurally generated 3D rig, a QR-accessible website with tap-to-learn components and
install-free WebAR, a Unity 6 project (URP + AR Foundation), and a four-sheet A3 poster.

> The 3D model is an **educational visualisation** generated by this project's own script.
> It is not CAD, not dimensionally exact and not a specific commercial product. No pressures,
> temperatures, refrigerant type, COP or other measurements are invented — lab values appear as
> editable placeholders in [`data/components.json`](data/components.json) → `labData`.

## 1. Regenerate the 3D model

Requirements: Python 3.10+ with `numpy` (`pip install numpy`).

```bash
python model-generation/generate_vcr_glb.py
```

This writes `model-generation/output/VCR_System.glb` (+ `_Exploded` variant used by the AR page),
`data/flow_paths.json`, `data/anchors.json`, and copies the GLB/data into `web/public/models` and the
Unity project. Each component is a top-level node `C01_Compressor … C12_Frame` (origin at its own
bounds centre) so apps can pick, highlight and explode it; fan rotors are `…_Rotor` child nodes.

Validate with the Khronos glTF-Validator and check node names against the data file:

```bash
cd web && npm run validate:model
```

Components: 1 Compressor · 2 Condenser · 3 Expansion device (TXV with sensing bulb) · 4 Evaporator ·
5 Receiver/filter-drier (illustrative) · 6 Condenser fan · 7 Evaporator fan · 8 Discharge line ·
9 Liquid line · 10 Suction line (insulated) · 11 Pressure gauges (illustrative, no readings) · 12 Frame.

## 2. Website

```bash
cd web
npm install
npm run dev            # http://localhost:5173
npm run build          # production build in web/dist (set BASE_PATH=/repo-name/ for GitHub Pages)
npm run preview
```

Pages (hash routes, so they work on any static host): `#/` home · `#/explore` 3D explorer ·
`#/components` library · `#/cycle` step-by-step cycle + schematic p–h sketch · `#/exploded` ·
`#/about` methodology · `#/references` · `#/ar` WebAR. Deep link a part with `#/explore?c=compressor`.

**Camera overlay** (`● Camera` button in the explorer, or `#/explore?overlay=1`): shows the rig over the live
camera feed — the rear camera on phones, the webcam on laptops — with every explorer control still working.
It works on devices without ARCore/Quick Look, but it is an overlay, **not surface-tracked AR**. The camera is
requested only when the button is pressed; denied / missing / busy cameras show a message and the 3D view
continues. Smoke test with Chromium's synthetic camera: `node web/scripts/test-camera-overlay.mjs`.

Explorer features: tap/click picking that ignores drags and UI, single-part highlight, info panel with
close / prev / next / zoom-to-part, ghost or isolate other parts, numbered callouts synced with the list,
explode slider, conceptual flow arrows coloured by refrigerant state, cycle player, keyboard
(←/→ next/prev, Esc close, R reset), larger-text toggle, loading/WebGL-error states, phone layout.

### AR approach (and its limits)
Unity AR Foundation does **not** provide camera AR inside ordinary WebGL, so the QR opens the website and
AR uses Google's `<model-viewer>`:

* **Android** – Chrome + Google Play Services for AR: WebXR or Scene Viewer.
* **iOS/iPadOS** – Safari: AR Quick Look (USDZ generated on the fly by model-viewer).
* **Everything else** – 3D view only; the page says AR is unavailable.

The camera is requested only when the user taps *View in your space*; a failed/denied session shows a
message and the 3D view keeps working. Hotspots 1–4 on the AR model open component cards.
**Real-device AR testing is still required** – it cannot be verified from a desktop.

### Regenerate screenshots / poster renders
With the dev server running:
```bash
cd web && node scripts/capture.mjs          # → poster/assets/*.png (+ *_anchors.json), public/img/hero.png
```
Uses the installed Edge/Chrome via `puppeteer-core` (`BROWSER_PATH` to override).

## 3. Deployment (GitHub Pages)

The workflow in `.github/workflows/deploy-pages.yml` validates the model, builds `web/` with
`BASE_PATH=/<repo>/` and publishes `web/dist`. One-time setup for a new repository:

```bash
gh repo create <owner>/VCR-AR-Explorer --public --source . --push
gh api -X POST repos/<owner>/VCR-AR-Explorer/pages -f build_type=workflow
gh workflow run deploy-pages.yml
```

`node_modules`, `dist`, Unity `Library/Temp/Logs/UserSettings/Builds`, APKs and `.env` files are ignored.

## 4. Unity project

* Editor: **Unity 6000.5.9f1** (Unity 6). Packages (versions bundled with this editor): URP 17.5.0,
  glTFast 6.14.1, Input System 1.20.0, uGUI 2.5.0, AR Foundation 6.5.0, ARCore XR Plug-in 6.5.0, XR Management 4.5.4.
* Active input handling: Input System (code also compiles for the legacy Input Manager).
* Open `Unity/VCR-AR-Explorer` in Unity Hub, then run **VCR ▸ Setup Project** whenever the GLB or data changes.
  It (re)creates URP settings, `Assets/Materials/*.mat` from the GLB's material table, `Assets/Data/VCRDatabase.asset`,
  `Assets/Prefabs/VCR_Rig.prefab` (MeshColliders + `VCRSelectable` on every component), the scenes
  `MainMenu`, `VCRExplorer`, `VCR_AR`, build settings, Android player settings and the ARCore loader.
* **VCR ▸ Validate Project** runs the checks listed in `Unity/logs/validation.txt`.

Batch mode (what was run to build this repo):
```bash
Unity.exe -batchmode -nographics -projectPath Unity/VCR-AR-Explorer -executeMethod VCR.EditorTools.VCRProjectSetup.SetupFromCommandLine -logFile Unity/logs/setup_unity.log
Unity.exe -batchmode -nographics -projectPath Unity/VCR-AR-Explorer -executeMethod VCR.EditorTools.VCRBuildAndValidate.Validate -logFile Unity/logs/validate_unity.log
Unity.exe -batchmode -nographics -projectPath Unity/VCR-AR-Explorer -executeMethod VCR.EditorTools.VCRBuildAndValidate.BuildWindows -logFile Unity/logs/build_windows_unity.log
```
Smoke test / screenshot of the built player:
```bash
Unity/VCR-AR-Explorer/Builds/Windows/VCR-AR-Explorer.exe -screen-width 1600 -screen-height 900 -vcrScene VCRExplorer -vcrSelect compressor -vcrShot C:/tmp/unity.png
```

Scripts (`Assets/Scripts`): `VCRData`/`VCRDatabase` (JSON + ScriptableObject), `VCRModelBinder`
(finds nodes by name, adds colliders), `VCRSelectable`, `SelectionManager` (tap vs drag, UI-safe raycasts,
ghost/isolate), `OrbitCameraController` (mouse + touch orbit/pan/zoom/reset), `ExplodeController`,
`FlowAnimator`, `CycleController`, `LabelManager` (numbered callouts), `VCRExplorerUI` (responsive uGUI),
`MainMenuController`, `VCRAutomation` (CLI smoke tests), `AR/ARPlacementController` (plane detection,
tap to place, pinch/twist).

**Native Android AR build:** install the *Android Build Support* module **with OpenJDK and Android SDK & NDK**
in Unity Hub, then run `VCR.EditorTools.VCRBuildAndValidate.BuildAndroid` (or File ▸ Build Profiles ▸ Android).
Requires an ARCore-supported phone. This build was run successfully here: `Builds/Android/VCR-AR-Explorer.apk`
(≈34 MB, not committed) — install with `adb install -r` and test on a real device. WebGL is not used (the module is not installed and is not needed – the
website provides the browser experience).

## 5. Poster (four A3 landscape sheets)

```bash
python poster/build_poster.py --url https://<owner>.github.io/VCR-AR-Explorer/
node poster/print_poster.mjs
python poster/verify_poster.py   # 4 pages, 420×297 mm, decodes every QR → poster/verification.json
```
Python packages: `qrcode`, `pymupdf`, `opencv-python-headless`, `numpy`. Without `--url` the QR areas are
clearly marked placeholders; localhost/non-https URLs are refused. Previews: `poster/previews/sheet-*.png`.
